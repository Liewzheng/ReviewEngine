## API Token 与 Bootstrap Key(认证指南)

> 如果你第一次部署、不熟悉这些词,先花两分钟读 §0。下面每个"专业词"出现时,都会先用大白话解释一遍,不会让你猜。

### 0. 先认识这些词(大白话速查)

**三个最关键的词,务必分清:**

| 概念 | 是什么(大白话) | 什么时候用 | 用错了会怎样 |
|------|---------------|-----------|-------------|
| **API Token**(登录密码) | 登录这个网页/接口要用的"密码",每次请求都带上它,服务器核对无误才放行 | 登录、日常使用 | 填错 → 401 登录不进去;把它当 Bootstrap Key 用 → 服务器不认 |
| **Bootstrap Key**(开荒钥匙) | 一把"开荒钥匙",只在**第一次设置密码**或**密码丢了要换一个**时校验;它**不是登录密码** | 第一次设密码、密码丢失时换新 | 把它当日常登录密码 → 401(它本来就不是登录密码) |
| **env token**(`.env` 里的密码) | 写在 `.env` 文件里的登录密码(变量名 `REVIEW_API_TOKEN`),和"网页里设的密码"是同一类东西,只是来源不同 | 部署时直接给、应急重置 | 改了 `.env` 不重启 → 不生效(env 只在启动时读);删了它又没 Bootstrap Key → 以后换密码很麻烦 |

**其他会遇到的词:**

| 词 | 大白话 |
|----|--------|
| **环境变量(.env 文件)** | 一个名叫 `.env` 的文本文件,一行一行写着"程序启动时要用的参数"。`docker compose up` 启动时会自动读它,把里面的值传给容器。你部署时改的 `REVIEW_API_TOKEN`、`REVIEW_BOOTSTRAP_KEY` 都写在这里。 |
| **auth.toml** | 服务器用来"记住密码"的文件(在 `./auth/auth.toml`)。它不存密码原文,只存一串"指纹"(见下一行)。 |
| **摘要 / SHA-256** | 一种"算指纹"的办法:把密码变成一串固定长度的乱码存起来。服务器不存密码原文——就算这个文件被偷走,也还原不出密码。 |
| **loopback / 127.0.0.1** | "只在自己机器内部转"的地址。绑定它 = 只有这台机器自己能访问,外面任何电脑都连不进来,所以安全。 |
| **0.0.0.0** | "对外网开放"的意思。绑定它 = 局域网内任何电脑都能访问这个端口(所以必须设密码,见 §1)。 |
| **localStorage** | 浏览器自带的"记事本"。网站把登录密码存在这里,你下次打开网页就不用重新输。 |
| **401** | 服务器回的一个数字,意思是"你没带密码,或者密码不对"。看到 401 = 登录没成功。 |
| **Bearer** | 请求里带密码的标准写法:`Authorization: Bearer <密码>`,翻译过来就是"我用这个密码来"。 |
| **env 优先** | 服务器每次启动都会**先看 `.env` 里有没有 `REVIEW_API_TOKEN`——有,就用它;没有,才用之前存进 `auth.toml` 的那个**。 |

### 1. 服务器第一次怎么拿到密码(三种方式)

| 方式 | 你要做什么 | 适合谁 | 大白话说明 |
|------|-----------|--------|-----------|
| A. 直接给 | 在 `.env` 里写 `REVIEW_API_TOKEN=<一串密码>` | 想一启动就能用、不想开网页设置 | 服务器启动时直接用 `.env` 里的密码,优先于任何之前存过的 |
| B. 引导设置(推荐) | 在 `.env` 里写 `REVIEW_BOOTSTRAP_KEY=<一把钥匙>` | 第一次部署 | 服务器先"空着密码"启动,你第一次打开网页时,网页让你填"自己想设的密码 + 这把钥匙",之后密码以"指纹"形式存进 `auth.toml` |
| C. 只在本机 | 什么都不用写 | 只在开发机/本机用 | 绑定 `127.0.0.1`(只在自己机器内部),外面连不进来,所以不需要设密码 |

**重要规则:只要服务器对外网开放(绑定 `0.0.0.0`,compose 默认就是),就必须在 A 或 B 里选一个,否则服务器拒绝启动。**

为什么:如果既没设密码、又对外网开放,那任何人都能抢在第一个打开设置页,把密码设成自己的,等于把你的服务整个劫持走。要求你二选一,就是保证"密码一定是你设的"。

### 2. 第一次部署(照着做就能通)

登录入口:默认 `http://<宿主IP>:18080`(compose 把容器里的 8080 映射到了宿主机的 18080);启用 HTTPS 后为 `https://<宿主IP>`(443)。

#### 方式 A — 用 Bootstrap 引导(推荐,大多数人的选择)

```bash
# 第 1 步:生成一把随机钥匙,写进 .env
# 这条命令在干什么:openssl rand -hex 16 随机生成 32 个字符的乱码(这把钥匙),
# 然后 "echo ... >> .env" 把这行追加到 .env 文件末尾,即给 .env 加上一行
# REVIEW_BOOTSTRAP_KEY=<钥匙>。服务器会用这把钥匙放行你第一次设密码。
echo "REVIEW_BOOTSTRAP_KEY=$(openssl rand -hex 16)" >> .env

# 第 2 步:启动服务
# 这条命令在干什么:按 .env 里的配置启动所有容器(第一次会自动构建/拉取镜像)。
docker compose up -d

# 第 3 步:浏览器打开 http://<宿主IP>:18080
# 第一次打开会看到"设置页",要填两样东西:
#   1) 你自己想用的登录密码(API Token),比如用下面这条命令生成一串:
#      openssl rand -hex 32
#   2) 刚才写进 .env 的那把钥匙(REVIEW_BOOTSTRAP_KEY 的值)
# 点保存后,服务器会把你的密码以"指纹"(SHA-256 摘要,不是明文)存进 ./auth/auth.toml。

# 第 4 步(可选):钥匙用完了,可以从 .env 删掉 REVIEW_BOOTSTRAP_KEY 那一行
# 在干什么:它只是"开荒钥匙",已经用完。删不删、有什么取舍,见第 3 节。
```

#### 方式 B — 直接把密码写进 .env(不想开网页设置)

```bash
# 第 1 步:生成密码并写进 .env
# 这条命令在干什么:随机生成 64 个字符的密码(openssl rand -hex 32),作为
# REVIEW_API_TOKEN 的值追加到 .env。注意:要"先生成、再写进去",不要直接在
# .env 里写 REVIEW_API_TOKEN=$(openssl rand -hex 32)——docker compose 不会帮你
# 执行这个命令,会把 $(...) 当普通文字原样存下来。
echo "REVIEW_API_TOKEN=$(openssl rand -hex 32)" >> .env

# 第 2 步:启动服务,然后用这个密码登录网页。
docker compose up -d
```

### 3. 换密码(轮换 token)

平时可以随时把登录密码换成新的。三种情况、三种做法:

| 你现在手里有什么 | 怎么做 | 大白话 |
|-----------------|--------|--------|
| 还记得现在的密码 | 网页右上角点 **API Token**,输入新密码保存 | 用旧密码证明"我是主人",然后把密码换掉 |
| 现在的密码丢了/失效了 | 网页 **API Token** 里输入新密码,同时填上 **Bootstrap Key** | 用那把"开荒钥匙"证明身份(它专门在这种时候用),然后换密码 |
| 上面两条都不行 | 改 `.env` 里的 `REVIEW_API_TOKEN` 为新密码,然后重启容器 | 因为"env 优先":服务器重启时会先看 `.env`,直接采用新密码,不认旧的 |

> **删掉钥匙前想清楚(重要取舍)**:`REVIEW_BOOTSTRAP_KEY` 用完可以删,它平时没用。
> 但它是你"密码丢了、不用重装就能自己换"的唯一凭证(上面第二行那条路)。所以:
> - 想省事、密码一般不会丢 → 删掉;
> - 想保留"忘记密码也能自己换"的能力 → 留着它(或留一个 `REVIEW_API_TOKEN`)。
> 删了之后密码又丢了,那就只能改 `.env` 重启,或删掉 `./auth/auth.toml` 重新走一次首次设置。

网页那边的行为:网页平时把密码记在浏览器的"记事本"(localStorage)里;一旦服务器回 401(密码不对),网页会自动把记事本里的密码清掉,并提示你重新输入;换密码失败时会提示"用 Bootstrap Key 重试"。

### 4. 一直 401 / 登录不进去?(三步排查)

**先讲清楚为什么会有 401**:浏览器记事本(localStorage)里记的是**旧的**登录密码;而服务器那边早就换成了**新密码**(可能你换过、可能你改过 `.env`、可能另一台浏览器改过)。于是浏览器每次都拿着旧密码去敲门,服务器一核对不对,就回 401。就这么简单,不是服务器坏了。

按顺序做:

1. **删掉浏览器记事本里的旧密码**——按 F12 打开开发者工具 → **Application**(应用)→ **Local Storage** → 找到 `review_engine_api_token` 这一条 → 删除 → 刷新网页。浏览器会重新问你密码,这时输**当前有效**的那个。90% 的 401 走到这一步就好。
2. **如果密码确实已经失效**——用 Bootstrap Key 换一个新的:网页右上角点 **API Token**,输入新密码 + Bootstrap Key,保存。这条专门救"密码真的丢了/被换过"的情况。
3. **还不行就改 .env 重启(env 优先)**——把 `.env` 里 `REVIEW_API_TOKEN` 改成新密码,然后:

```bash
# 这条命令在干什么:强制按最新 .env 重建容器(让新密码生效),然后网页回到第 1 步清一次记事本再重登。
docker compose up -d --force-recreate
```

**看报错区分两种情况**:服务器回的错误里有一串代码:
- `{"code":"unauthorized"}` = 密码**已经设过**,但你带的不对(没带/带错/带旧的)→ 走上面三步;
- `{"code":"auth_required"}` = 服务器**还没设过密码**(第一次引导阶段)→ 去第 2 节方式 A 走首次设置,不是密码填错。

### 5. 术语表(查漏补缺)

| 词 | 大白话 |
|----|--------|
| API Token | 登录密码;所有请求都带着它,服务器核对后才放行 |
| Bootstrap Key | 开荒钥匙;只在"第一次设密码 / 密码丢了换新"时用,平时用不到,不是登录密码 |
| env token | 写在 `.env` 里的密码(`REVIEW_API_TOKEN`);服务器启动时优先用它 |
| bootstrap mode | 服务器"还没设密码"的首次运行状态;此时普通接口都会回 `401 auth_required` |
| `REVIEW_AUTH_FILE` | 存密码指纹的文件,默认 `./auth/auth.toml`(容器内 `/app/auth/auth.toml`) |
| loopback bind | 绑定 `127.0.0.1` / `::1` / `localhost` = 只在自己机器内部,外面连不进 |
| SHA-256 摘要 | 密码的"指纹":服务器只存指纹不存原文,文件被偷也还原不出密码 |
| env 优先 | 服务器启动先看 `.env` 的 `REVIEW_API_TOKEN`,有就用它,没有才用 `auth.toml` 里存的 |

## 容器部署排查

### 启动报 `Bind mount failed: <dir> does not exist`?

先说"bind mount(挂载卷)"是什么:容器里的部分文件夹是从宿主机"借"来的——两边其实是**同一个文件夹**,容器里写的会直接落在宿主机那个目录里。

Linux/NAS 上这些被借用的目录如果不存在,**docker 不会帮你自动创建**,启动就会报这个错。所以先手动建好:

```bash
# 在干什么:一次性创建容器要借用的几个目录,都建在当前目录下。
# tls 仅启用 HTTPS 时需要,其余必建。
mkdir -p config reports bin frontend-dist auth tls
```

### 容器日志报 `cp: Permission denied`(写卷失败)?

原因大白话:宿主机上的文件夹归"宿主机的某个用户"所有;容器里跑程序的是一个叫 `review-engine` 的用户,它想去写这些文件夹,但文件夹不是它的,没权限,于是报 `Permission denied`(没有权限)。

解决:把文件夹的"主人"改成容器里那个用户(`chown` 就是"换主人"命令):

```bash
# 在干什么:把下面几个目录的属主改成 <容器UID> 这个用户,容器里的 review-engine 才有权写。
sudo chown -R <容器UID>:<容器UID> bin frontend-dist auth config reports tls
# UID 是多少:用下面这条命令查镜像里 review-engine 用户的编号,以实际输出为准
#   docker run --rm --entrypoint id ghcr.io/liewzheng/review-engine:latest review-engine
# v0.9.13+ 镜像固定 9001。Docker Desktop(macOS/Windows)自动处理,无此问题。
```
